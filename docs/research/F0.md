## 3. Qué funcionó / qué no

- Funcionó: lectura socket P1 (socket directo, sin depender del binario `hyprctl`),
  sysfs P2, parsing EDID P3, listener P4 (reposo), reconciliación P5, 14 tests.
- No probado aún: **hotplug físico HDMI** (conectar/desconectar cable con P4
  corriendo y observar `monitoraddedv2>>/monitorremovedv2>>` + `configreloaded>>`).
  Es el único punto pendiente del criterio de finalización; requiere acción física
  del usuario (procedimiento en §7).
- Sin fallos ni errores ocultados: build sin warnings.

## 4. Discrepancias encontradas

1. `hyprland` crate 0.3.13 (docs.rs): tipos `Monitor` desactualizados frente a
   Hyprland 0.56 (campos nuevos `solitary`, `tearingBlockedBy`, `sdr*`, `mirrorOf: "none"`).
   Decisión: P1 usa structs propios con `#[serde(default)]` → tolera campos nuevos y
   ausentes. No fijar versión del crate como verdad.
2. `availableModes` (1 modo) vs expectativa de TV multirrango: es el panel interno,
   no un bug. Para TV externa se esperan N modos; P5 ya compara por WxH.
3. DRM `modes` no incluye Hz (`1920x1080` pelado) mientras Hyprland da
   `1920x1080@60.00Hz`. P5 solo cruza WxH y conserva Hz Hyprland con 3 decimales.
4. `serial` Hyprland vacío aunque EDID trae serie (0) y nombre: no usar `serial`
   del compositor como identidad.
5. En F1 el `stable_id` debe usar SHA-256 real; F0 usa FNV-1a de 8 hex como
   placeholder documentado (`sdc-4161-3b28cae1`: formato válido, hash provisional).

## 5. Comportamiento hotplug / socket2 (pendiente de cable)

Procedimiento para cerrar F0:

```bash
./target/debug/socket2-listener            # terminal 1 (sin timeout)
./target/debug/reconcile                   # terminal 2, antes de conectar
# conectar HDMI, esperar 3 s
./target/debug/reconcile                   # debe aparecer Display HDMI-A-N con EDID + modos
./target/debug/edid-probe /sys/class/drm/card1-HDMI-A-1/edid
# desconectar HDMI, comprobar monitorremovedv2>> en terminal 1
```

Éxito esperado: `monitoraddedv2>>ID,HDMI-A-N,desc` → `configreloaded` →
P5 muestra el HDMI con `Hyprland + DRM + hash`; al desconectar, `monitorremovedv2>>`.

## 6. Decisiones que pasan a F1

1. `display-core`: structs `Monitor/Mode` = los de P1/P5 (`#[serde(default)]`,
   `hz: f64` sin redondeo, tolerancia ±0.5 solo en comparación).
2. `backend-hyprland`: socket directo `.socket.sock` (`j/monitors all`), no
   `Command hyprctl` como camino principal; `hyprctl` queda como fallback/debug.
3. `drm-probe`: reutilizar P2 tal cual (filtro y `short_name` validados por tests).
4. `edid`: P3 + SHA-256 + DTDs completos (resolución/Hz por descriptor, no solo nombre).
5. Identidad: `pnp-product-hash128` con `connector_hint` separado; fixtures
   `monitors.json` + `edp1-edid.bin` ya guardados en `f0/*/tests/fixtures/`.
6. Eventos: P4 + debounce + reconciliación P5 como núcleo del futuro daemon.
