## 1. Snapshot (Observed + Decision)

`Snapshot{taken_at, outputs[], workspaces[], focused_output, raw_monitors,
raw_workspaces}`; por output: `OutputState` (modo/posición/escala/disabled/
mirror) + `transform` + `vrr` + `focused` + `active_workspace`. Campos nuevos
en `HyprMonitor`: `transform`, `vrr`, `focused`, `activeWorkspace{id,name}`.
**Limitación observada:** `monitors -j` no expone `bitdepth`/color-management;
se documenta y no se finge restaurarlo. Persistencia en
`$XDG_STATE_HOME/rosadeck` (o `~/.local/state/rosadeck`):
`snapshot-<ts>.json` vía tmp+fsync+rename + symlink `last`.

## 2. Plan (Decision)

`crates/planner` puro (sin IO): `DisplayRequest{kind,target,policy,
requested_mode,position}` → `DisplayPlan{steps[], expect[], min_enabled,
exact_enabled}`. `MonitorCommand::to_keyword_arg()` serializa
`NAME,RES@RATE,XxY,SCALE[,mirror,O][,transform,N]` o `NAME,disable`; Hz con
roundtrip corto (`60`, `59.997`). Duplicate: espeja externa→interna, modo
común vía `intersect` + `select_mode` (nunca `min()`). External-only: orden
**configurar→verificar→deshabilitar** (nunca al revés). Extend: posiciones
right/left/up/down desde píxeles de modo; escalas del usuario intactas.
Validación `validate_last_output` cuenta outputs no tocados: imposible plan
con 0 enabled (tests).

## 3. Executor (Decision)

`CommandRunner` trait (mock en tests; `cargo test` nunca toca pantallas) +
`HyprctlRunner` (binario `hyprctl` version-matched; el framing de escritura
directa por socket es sensible a versión y no está documentado para mutar —
se deja el swap tras el trait). 1 paso → `keyword`; N pasos → un `--batch`
`keyword monitor A ; keyword monitor B`. **Atomicity boundary:** el batch es
secuencial best-effort, no atómico; fallo a mitad = stop + restore.

## 4. Verify (Decision)

`check_plan` (presente, enabled, modo ±0.5, mirror, posición, conteos
min/exact) sobre `unify()` re-leído — nunca sobre el stdout del comando.
`verify_plan`: 6 intentos × 400 ms ≈ 3 s (baseline F0/F2), sin loops infinitos.
EDID corrupto degrada a warning sin perder estado del compositor.

## 5. Restore (Decision)

`build_restore_plan(snapshot, connected_now)`: re-aplica modo/pos/escala/
mirror/disabled/transform grabados; salta outputs desaparecidos (HDMI
desconectado); si quedaría 0 enabled, fuerza la interna del snapshot.
`run_transition`: apply → verify → `RolledBack`, o restore → verify →
`RESTORE_FAILED` (terminal, requiere recuperación manual). Sin ruta
`unsafe_apply`: el snapshot es argumento obligatorio.

## 6–8. Duplicate / External Only / Extend
